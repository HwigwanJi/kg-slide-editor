# 장표 밀도·도형 규칙 — Gap Analysis (DENSITY.md)

레퍼런스(케인즈그룹/공공 컨설팅 분석 장표)를 정량 분석해 도출한 "고밀도 도식화" 규칙.
컨설팅 장표가 허접해 보이는 1순위 원인은 **도형이 적고, 분해가 덜 되고, 색 위계가 거꾸로** 되어서다.

---

## 0. 작도 프로세스 (Iterative Fill Loop) ★★★ — 반드시 이 순서로
## 0. 작도 프로세스 (Drawing Process) ★★★ — 반드시 이 순서로
> 장표 그리는 건 **논리싸움이자 전달력싸움**이다. 여백은 결과지 목표가 아니다.

### STEP 1. 코호트 분류 (무엇을 위한 장표인가)
- **정보전달형** — 세부 내용·깊이가 핵심(정의·근거·수치·절차). 다수 박스+표+유목화, 균형 그리드.
- **시선강탈형** — 큰 도식·시각화·스토리 흐름이 핵심(개념·전환·관계). 중심 오브젝트 1개+위성 콜아웃.
- 한 장이 둘 다면 주(主) 코호트를 정하고 종(從)은 보조로.

### STEP 2. 필수 내용 기획 (논리)
- 이 장의 **주장(헤더 메시지) → 이를 받치는 논리 블록**을 먼저 텍스트로 확정.
- 근거·수치·사례가 부족하면 **추가조사**(1차자료·통계) 후 채운다. *비면 추정치 표기(*재확정).*

### STEP 3. 세부 작도 계획 (전달력)
- 코호트별 **레이아웃 골격**(소주제 비율 1:3·2:2·3:1·5:3) 선택.
- **컴포넌트 배정**: 어떤 x 모듈(도넛·막대·flow·벤·셰브론…)·연결선(사다리꼴·삼각·mesh)·Box-in-Box를 어디에 쓸지 명시.
- **비컴포넌트로 그릴 것**(로컬 커스텀): 무엇을·왜 손그림하는지 적고, 반복되면 컴포넌트로 승격.

### STEP 4. 감사 (다지표 점검) — 스크린샷으로 눈 확인
- **린터**: 콘솔·오버플로우·겹침 0
- **여백률**: 흰 생짜 여백 0, 하단 마진까지 채움 (박스 내부 gap 없음)
- **컴포넌트 사용률**: box-in-x ≥50% · 연결선 위계 ≥50% · Box-in-Box ≥50% (모두 GREEN)
- **시각적 전달성**: 시선 동선 1개, 결론(red/navy) 1곳 수렴, 코호트 의도 달성
- **심미성**: 무채색 50~70%:파랑 25~35%:강조 ≤5%, 정렬·크기 위계

### STEP 5. 세부조정 (반복)
- STEP 4 지표가 **모두 만족될 때까지 STEP 3–4–5를 반복**한다.
- 여백이 남으면: (a) 새 컴포넌트 추가 / (b) 내용 부풀리기(유목화 하위줄·사례) / (c) 핵심 오브젝트 확대 — 택1 후 재감사.
- 박스는 **내용 기준으로 shrink**(`flex:0 auto`) 후 남는 공간을 위 3택으로 메운다. 한 번에 끝내지 않는다.

## 1. 도형 수 (Shape count) — 기본은 MAXIMAL

| 모드 | 한 영역(컬럼/사분면)당 | 한 장표 전체 |
|---|---|---|
| 미니멀(요약) | 키워드 박스 4~6 | 라벨 박스 12~18 |
| **맥시멀(분석) ← 기본** | **키워드 박스 8~16** | **라벨 박스 30~60 + 연결선 10~20** |

- 분석 장표의 표준은 맥시멀. **여백이 보이면 "구성요소로 더 쪼개라"** 는 신호.
- 레퍼런스 1장(산업규모 산정) 실측: 좌 13 + 중 3 + 우 3 + 중첩 5 = **약 24개 박스**, 연결선 약 15개.
- 한 박스 = 한 키워드(2~6자 명사). 문장은 박스 밖(우측 메시지/하단 해석)으로 분리.

## 2. 색상 강약 — fill 농도로 위계 (색을 늘리지 말 것)

위계는 새 색이 아니라 **채움(fill) 4단계**로 만든다. **주력 fill은 "연한 파랑"이다.**

1. **흰 박스 + 1px 테두리** = 원자료·세부 항목 — 전체의 **60~70%** (가장 많음)
2. **연파랑 fill** (`blue-100/200`, 그라데이션) = 주요 분석 단위·중간 산출 — **20~30%**
3. **네이비 fill** = 그 구조의 **단 하나의 핵심 결론/노드** — **5% 이하** (아껴서)
4. **빨강 테두리/라벨** = 신규·제외·위험·주의 — 점적으로

> 네이비 fill 남용이 "허접함"의 핵심 원인. 네이비는 **헤더 바·번호 뱃지·구조당 1개 결론**에만.
> 큰 블록 화살표는 연회청색(저강도) — 흐름만 표시하고 내용과 경쟁하지 않는다.

## 3. 박스 방향 · 컬럼 구조

- **입력(원자료) = 가로 행(row)으로 나열**, **산출(도출물) = 세로 스택(column)으로 정렬** 하는 경우가 많다.
- 한 영역 = 보통 **2~3개의 내부 컬럼**: `[입력] → [중간] → [산출]`. 컬럼 사이는 얇은 선 또는 작은 삼각 화살표.
- 세로 스택은 **같은 폭으로 좌우 정렬**, 가로 행은 등분.
- 좌측에 **소형 행 라벨**(내부역량/외부환경, 공제구성/차감구조)로 묶음을 구분.
- 사분면(2×2) 프레임워크: 각 사분면이 자체 `입력→중간→산출` 미니 다이어그램을 가진다.

## 4. 겹침(overlap) 규칙

- **박스끼리는 겹치지 않는다.** 관계는 연결선으로.
- 허용되는 겹침은 셋뿐:
  1. **번호 뱃지**가 박스 좌상단 모서리에 걸침
  2. **큰 블록 화살표**가 박스군 사이/뒤에 살짝 깔림
  3. 그룹을 감싸는 **브래킷 / 점선 권역**
- 박스-in-박스: 부모 박스 영역 안에 자식 박스를 **들여쓰기(indent)** 로 중첩 (예: 종목사 매출 → 스폰서십/중계권/티켓…).

## 5. 연결선 위계 (Connectors)

| 종류 | 용도 |
|---|---|
| 가는 선(hairline 0.6~1px) | 다대다 매핑·군집↔군집 (부채꼴 mesh) |
| 작은 삼각 화살표 | 1:1 흐름 |
| 블록 셰브론(대형, 연회청색) | 단계·사분면 전환 |
| 점선 | 검토·가설·비합산 등 약한 관계 |

- 다대다는 **모든 조합을 다 긋지 말고**, 각 입력→인접 1~2개 산출로 mesh를 암시(저투명도).
- 연결선은 박스 사이 **흰 공간 위로만** 교차. 박스 위를 지나가지 않는다.

## 6. 체크리스트 (장표 완성 전)

- [ ] 한 영역에 박스가 8개 이상인가? (아니면 더 쪼갠다)
- [ ] 네이비 fill이 구조당 1개 이하인가? 주력 fill이 무채색·연파랑인가?
- [ ] 입력은 가로, 산출은 세로로 정렬했는가?
- [ ] 컬럼이 2~3단계(입력→중간→산출)로 흐르는가?
- [ ] 연결선이 관계를 설명하는가(장식이 아닌)?
- [ ] 키워드 박스 안은 명사 키워드뿐인가? (문장은 밖으로)

## 7. 핵심 레이아웃 공식 (리뷰로 합의된 규칙) ★

레퍼런스 리뷰에서 반복 확인된, 가장 중요한 규칙들. 모든 본문 장표는 아래를 따른다.

### 7-1. 3/4 + 1/4 (가장 안정적인 본문 골격)
- **좌측 3/4 = 밀도 높은 분석 본문**(차트·박스·다이어그램), **우측 1/4 = 시사점 블록 여러 개**(3~5개).
- 좌→우를 연결선 또는 **사다리꼴 그라데이션**으로 잇는다. 우측 마지막 블록은 결론(네이비).

### 7-2. 항상 가득 채운다 (Fill)
- 본문은 **아래 여백까지 가득** 채우되 균형 있는 외곽 여백 유지. 빈 공간이 보이면 분해가 덜 된 것.
- 박스는 `flex:1`로 높이를 채우고, 내용은 세로 중앙 또는 균등 분배(`space-between`).
- TOC·간지도 동일 — 챕터 블록을 세로로 균등 분배해 하단까지 채운다.

### 7-3. 계층화 (Nesting) — box-in-box / box-in-chart / box-in-box-in-box
- **큰 덩어리 박스 금지.** 모든 박스는 더 작은 박스/차트/그룹으로 쪼갠다.
- 한 컬럼 = [헤더] + [차트 박스] + [텍스트 박스] 처럼 **기능별로 박스를 분리**(box-in-box).
- 차트 안에도 라벨 박스, 박스 안에도 번호 하위 박스 — 2~3겹 중첩으로 밀도를 만든다.
- **각 하위 항목 안에 미니 flowchart를 넣는다.** 예: "현금흐름 제약 실재" 아래 →
  `[영세제작사 공제 미활용] → (화살표) → [재투자 지연]` + 그 아래 별도 텍스트 박스.
- 목표 밀도: 지금 그리는 요소의 **2배 이상**. 통계에는 **제목 박스**(예: "공제 실현율")를 붙여 무슨 수치인지 명시.
- 차트는 혼합형(막대+추세선)·도넛·100% 스택 등 **종류를 다양하게**, 글자가 작아질 바엔 **차트 영역을 키운다**.

### 7-4. 유목화 (Grouping) — 나열 금지
- 평면 bullet 나열 금지. **핵심키워드(sub-head) → 하위 내용 2개** 묶음으로 구조화(`.kg-grp`).
  ```
  ▪ 핵심키워드1      ▪ 핵심키워드2
    – 내용1            – 내용1
    – 내용2            – 내용2
  ```

### 7-5. 시각화 우선 (글자만 주지 않기)
- 도넛/파이(`conic-gradient`)·막대·스펙트럼 축·O/X·아이콘 등으로 **수치를 시각화**.
- "어떻게 하면 글자 대신 그림으로 보여줄까?"를 항상 먼저 묻는다.

### 7-6. 표 대신 박스 그리드
- `<table>` 사용 금지. `display:grid` + div 박스로 **표처럼 보이게** 그린다(handcraft).
- 헤더 셀(네이비/그레이), 기준 열(그레이), 강조 열(red-050 등), 셀은 흰/연그레이.

### 7-7. 연결선 = 내용 매핑 (장식 금지)
- 선은 **실제 관계가 있을 때만**, 출발/도착이 내용과 정확히 대응되게 긋는다.
- 행이 안 맞거나 다대다로 어설프면 **선 대신 사다리꼴 그라데이션**(출발 불투명→도착 투명)으로 영역을 잇는다.

### 7-8. 무채색 우선 (눈의 피로 방지)
- 캔버스·빗금·원자료/보조 박스는 **무채색**. 파랑은 분석·결론·헤더에만. 비율 무채색 60–70% : 파랑 25–35% : 네이비/빨강 ≤5%.

### 7-9. 번호/단계 라벨
- 박스가 있으면 **좌상단 모서리에 박스 높이 ~1/4 크기로 겹쳐서** 올린다(`.kg-cornern`).

### 7-10. 요소를 키워서 때우지 않기
- 빈 공간을 큰 박스/큰 글자로 때우는 습관 금지. **더 많이·더 작게·더 깊게** 쪼개 밀도를 올린다.

- [ ] 박스마다 미니 flowchart 등 `x`로 시각화 (단조로운 4박스 나열 금지)

## 9. box-in-**x** + text — 내부 콘텐츠 모듈(x) 카탈로그 ★★

모든 박스의 본질은 `[제목/번호] + [x] + [text]`. **x를 무엇으로 채우느냐**가 밀도와 완성도를 가른다.
"그냥 박스 안에 박스 4개"는 단조롭다 — 아래 모듈을 **군데군데 섞어** 리듬을 만든다.

### 9-1. 차트류 (수치 → 그림)
- **도넛/파이** `conic-gradient` — 비율 1개 강조 (실현율 62%)
- **막대** — 단계별 감소/비교 (인정100→실현62→소멸38)
- **혼합형(막대+추세선)** — 흐름과 수준 동시 (가장 컨설팅다움)
- **라인** — 시계열 추이 (매출·수출 CAGR)
- **100% 스택 바** — 구성비 (영세 88.6% / 대형 11.4%)
- **게이지·진척 바** — 달성도·단계 진행
- **스펙트럼 축** — 양극 사이 위치 (비환급 ↔ 환급형, 국가 핀)

### 9-2. 흐름/관계류 (★ 가장 자주 섞을 것)
- **미니 flowchart** — `[키워드]›[키워드]›[키워드]` 2~4노드. **박스 안 곳곳에 넣으면 예쁘다.**
- **환류 loop** — 가로 플로우 + 상단 피드백 화살표 (지원→수행→성과→환류·점검)
- **value chain / 단계 chevron** — `투입›과정›성과›파급효과` 셰브론 헤더 행 (roadmap형)
- **조직도 / 허브-스포크** — 중앙 노드 + 분기 + 양방향 라벨 화살표 (추진체계)
- **사다리꼴 그라데이션** — 크기·행이 다른 두 영역 연결 (불투명→투명)

### 9-3. 구조/프레임류
- **box-in-box 번호 리스트** — 부모 박스 + 번호 하위 박스 (들여쓰기)
- **box-grid (표 대체)** — div 그리드, 헤더/기준열/강조열 색 구분
- **SRPO·2×2·삼각 프레임** — 사분면/삼각 도형 + 주변 질문·근거 블록
- **매트릭스** — 행×열 박스, 핵심 셀만 강조

### 9-4. 보조류
- **타임라인/연혁** — 세로 라인 + 연도 dot + 태그(개편/현안)
- **지도 + 포인트** — 권역·거점 표시
- **콜아웃 / 스탬프 / 인용** — Illustrative, 현장 발언
- **사례 이미지 그리드** — `<image-slot>` + 캡션 바 (장르·사례)
- **O/X · 체크 · 아이콘** — 가부·충족 여부

### 9-5. 운용 규칙
- 한 장표에 **차트 1~2 + 미니 flowchart 2~3 + 프레임/그리드 1**처럼 **x를 섞는다**.
- x는 항상 **text(해석)와 한 쌍**: x는 사실, text는 "그래서 무엇인가".
- x가 비면(여백) 더 작은 x로 쪼갠다 — 큰 빈 박스 금지.
