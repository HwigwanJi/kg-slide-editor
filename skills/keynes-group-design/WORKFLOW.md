# 케인즈그룹 장표 워크플로우

장표 한 장이 만들어져 사람 손을 거쳐 최종본이 되기까지의 규약.
이 파일이 워크플로우의 유일한 진실이다. 대화 컨텍스트에 기억시키지 않고 훅이 매번 읽어 넣는다.

**읽는 법** — 굵게 쓴 문장과 명령줄은 그대로 따른다.
표와 코드 조각은 형태를 보이려고 든 것이지 목록이 아니다. 거기 없는 경우가 훨씬 많다.
판정의 진실은 검사 도구이고, 사람이 확인해야 넘어가는 지점은 이 파일 맨 끝에 있다.

## 전체 흐름

```
[입력]  레퍼런스 이미지 / 기존 장표(pptx·png) / 원문 텍스트
   │
   ▼
[1] 작도    keynes-group-design 스킬로 KG 장표 HTML 1장 생성
   │        └ 끝에서 타입 확정 질문(작도 cooldown) → types/ 카탈로그 갱신
   ▼
[1.5] 문구  AI-Polish 규칙으로 다듬는다 (검사 도구가 일곱 가지를 자동으로 짚어 준다)
   │
   ▼
[2] 검사·미리보기  node tools/lint.mjs → 지적 0건 → node tools/preview.mjs → PNG
   │        └ 사용자에게 PNG 를 보여 주고 방향 확인
   ▼
[3] 적재    node tools/ingest.mjs <폴더> → slides/*.kgslide + deck.json 등록
   │
   ▼
[4] 트리밍  사람이 직접 편집 · 또는 AI 가 커맨드 발행
   │        └ AI 는 HTML 을 다시 그리지 않는다 (DECISIONS D2)
   ▼
[5] 반복    미리보기 → 피드백 → [4] 로 되돌아감
   │
   ▼
[출력]  HTML / PNG / 프로젝트 폴더 전체
```

## 1단계 — 작도

**입력을 받으면 먼저 물어본다.** 물어보지 않고 진행하지 않는다.

| 질문 | 선택지 |
|---|---|
| 원본 존중 여부 | ① 원본 구조 그대로 옮김 ② 추천 타입으로 재구성 ③ 원본 유지 + 밀도만 보강 |
| 배치 위치 | 새 장표 / 기존 프로젝트의 몇 번째 |

레퍼런스가 이미지(캡처·pptx 슬라이드)면 다음 순서로 읽는다.

1. 상단 위계 파악 — 섹션번호 · 제목 · 세부주제 · 챕터탭 · 헤더 메시지
2. 본문 구조 파악 — 몇 개의 소주제로 갈리는지, 각 소주제 안이 어떤 도해인지
3. 그 도해를 KG x 모듈(도넛·막대·셰브론·허브스포크·매트릭스·타임라인 등)로 갈아끼움
4. 원문 문구는 살리되 문체는 공공기관 보고서체(명사형 종결)로 정리

**빈 박스를 막는 3중 장치**

큰 박스에 내용 두세 줄만 얹히면 "채우다 만 장표"로 보인다. 세 겹으로 막는다.

1. **작도 단계** — 칸을 먼저 세고 내용을 맞춘다.
   3칸짜리 열에 항목이 2개뿐이면, 빈칸을 두지 말고 ① 항목을 하나 더 찾거나
   ② 칸 수를 2개로 줄이거나 ③ 그 열의 비중을 줄여 다른 열을 넓힌다.
   `justify-content:space-between` 으로 벌려 놓는 것은 해결이 아니다 — 가운데가 비어 보인다.
2. **채우는 방식** — 칸마다 `flex:1` 을 주어 균등 분할하고, 남는 여백은 칸 사이 간격(`gap`)과
   칸 안 여백으로 흡수시킨다. 박스는 그대로 두고 내용이 고르게 퍼지게 만든다.
3. **기계 검사** — 그리고 나서 반드시 돌린다.
   ```bash
   node tools/lint.mjs <장표>
   ```
   박스 채움 비율이 기준 미만이면 "박스가 헐거움"으로 잡힌다. 기준은 `kg.config.json` 의
   `minFillRatio`. 지적이 남은 채로 다음 장으로 넘어가지 않는다.

**글자 크기 하한**

프로젝트마다 다르므로 `kg.config.json` 이 정한다. 코드나 장표에 숫자를 박지 않는다.

| 항목 | 기본값 | 대상 |
|---|---|---|
| `minBodyFontSize` | 14 | 본문 1~4단 |
| `minFontSize` | 13 | 제목·소제목·각주 |
| `minLabelFontSize` | 12 | 태그·번호 배지 |

작게 쓰고 싶어지면 글자를 줄이지 말고 **내용을 줄인다**. 검사가 하한 미달을 전부 잡아낸다.

**한 상자에 서식이 다른 덩어리를 섞지 않는다**

편집기는 글자 덩어리 하나를 편집 단위로 잡는다. 한 상자 안에 크기·색이 다른 글자가 섞여 있으면
위계도 하나만 붙고, 사람이 각각을 따로 고칠 수 없다.

```html
<!-- 나쁨 — 서식 태그로만 구분했다. 편집기가 한 덩어리로 본다 -->
<div class="cell"><b>핵심사업</b><em>수혜가치</em></div>

<!-- 좋음 — 덩어리마다 요소를 준다. 각각 위계가 붙고 따로 고칠 수 있다 -->
<div class="cell">
  <div class="cell__k" data-kg-role="h3">핵심사업</div>
  <div class="cell__v" data-kg-role="body2">수혜가치</div>
</div>
```

`<b>` · `<strong>` 은 **한 문장 안에서 일부 단어를 강조할 때만** 쓴다.
`명목 지원액 <b>100</b> 확정` 처럼 느슨한 글자와 섞여 있으면 한 문장이 맞고, 나누면 오히려 불편하다.
줄이 나뉘거나 서식이 통째로 다르면 요소를 나눈다.

**작도할 때 반드시 지킬 것**

- `data-kg-role` 을 직접 붙인다. 편집기가 추론으로 메우기는 하지만, 스킬이 붙이면 정확하다.
  위계: `title` `subtitle` `message` `h1` `h2` `h3` `body1`~`body4` `caption` `label` `label2` `num`
- 상단 위계(헤더·메시지띠·꼬리말)는 고정 구조를 벗어나지 않는다. 편집기가 자동으로 잠근다.
- 표(`<table>`) 금지. `display:grid` 박스 그리드로 만든다.
- 큰 빈 박스 금지. 모든 박스 안을 x 모듈로 채운다.
- 자산 경로는 `../assets/...` 로 쓴다. 편집기가 임포트할 때 알아서 바꾼다.

## 1.5단계 — 문구 다듬기

작도가 끝나면 **바로 이어서** 문구를 훑는다. 나중에 몰아서 하면 이미 여러 장이 같은 티를 달고 있다.

규칙집은 `AI-Polish` 스킬(`~/.claude/skills/AI-Polish/SKILL.md`) 하나다. **먼저 그것을 읽는다.**
`ai-polish` 로도 보이지만 같은 파일이다(윈도우는 대소문자를 구분하지 않는다). 고칠 때 한쪽만 고치는 일은 없다.
아래는 장표에서 자주 걸리는 갈래이고 전부가 아니다. 어디에 걸렸는지는 검사 도구가 짚어 준다.

| 갈래 | 고치는 방향 |
|---|---|
| 장식 기호 `▣ ■ ◆ ★ ※ ✓` | 굵게 처리하거나 번호 체계로. 원문자 `①②` 와 화살표 `→` 는 도해용이므로 그대로 둔다 |
| 완성형 종결 `~합니다 ~입니다` | 명사형으로. "제공함" "확보" "수행" |
| 자기변명 `~이 아니라` `한계가 있` | 사실만 적는다. 한계는 별도 항목으로 |
| AI 작업 흔적 `자동 산출` `생성 시각` | 작성 방법을 드러내지 않는다. 결과만 |
| 친절조 `참고로` `해 주십시오` | 사실 진술로 |
| 과장 `사상 최초` `혁신적` `압도적` | 근거만 남긴다. 판단은 발주처가 한다 |
| 영문 과잉 `Top 10` `MVP` | 한글 우선 + 괄호 병기 |

기계가 못 잡는 것은 사람과 AI 가 규칙집을 보고 직접 고른다. 특히 두 가지를 조심한다.

- **즉석 조어** — 머리로 만든 표현 대신 그 분야 정부기관 표준 용어를 쓴다.
  모르면 추측하지 말고 확인한다.
- **을의 신분** — 용역 수행사는 발주처에 단정하지 않는다.
  "이렇게 바꿨다"가 아니라 "이렇게 제안함".

원본 pptx 의 문구를 옮길 때는 **원문을 그대로 베끼지 말고** 위 기준으로 다시 쓴다.
다만 기관명·제도명·수치는 원문 그대로 둔다.

## 2단계 — 검사와 미리보기

검사를 먼저 돌린다. 지적이 남은 장표를 사람에게 보여 주지 않는다.

```bash
node tools/lint.mjs <입력>      # 위계·글자 하한·넘침·이탈·빈 박스·문구
node tools/preview.mjs <입력> [-o 출력.png]
```

검사 규칙은 편집기 코어를 그대로 번들해 돌린다. 화면에서 보이는 것과 검사 결과가 갈라지지 않는다.
종료 코드 1 이면 지적이 남아 있다는 뜻이다.

Playwright headless Chromium 으로 1280×905 를 그대로 찍는다.
html2canvas 계열 재현기는 KG 의 그라데이션·clip-path·웹폰트를 뭉개므로 쓰지 않는다(DECISIONS D3).

**PNG 를 사용자에게 보여 주고 다음을 묻는다.**
- 구조가 의도한 대로인가
- 밀도가 과하거나 부족하지 않은가
- 다음 장으로 갈지, 이 장을 더 다듬을지

## 3단계 — 적재

프로젝트 폴더 구조는 계약이 정한다.

```
프로젝트/
  deck.json          순서·제목·시각만. 장표 내용은 담지 않는다
  slides/*.kgslide   장표 한 장 = 파일 하나
  preview/*.png      장표별 미리보기
  library/*.svg      도형 라이브러리(점편집 아님 — 배치·색토큰·텍스트슬롯까지)
```

장표 HTML 을 `source/` 에 두고 넣는다.

```bash
node tools/ingest.mjs <프로젝트폴더>            # source/ 안의 html 을 전부 적재
node tools/ingest.mjs <프로젝트폴더> <a.html>   # 하나만
```

`slides/<id>.kgslide` 를 쓰고 `deck.json` 목차에 등록한다.
같은 원본을 다시 넣으면 id · 순서 · 미리보기 경로는 그대로 이어진다.

**다만 `.kgslide` 는 통째로 다시 쓰인다. 쌓아 둔 편집분(patches)은 사라진다.**
그래서 재적재는 **사람이 아직 손대지 않은 장표**에만 쓴다.
이미 편집한 장표의 문구·서식·위계를 고칠 때는 4단계의 `apply` 커맨드 경로를 쓴다.

그 다음 편집기에서 "폴더 열기"로 이 폴더를 연다.

## 4단계 — 트리밍

**사람** — 편집기에서 직접. 모든 기능은 툴바·우클릭·버블 툴바·Ctrl+K 명령 목록에 노출되어 있다.

**AI** — `core/commands.ts` 의 커맨드 JSON 을 발행한다. HTML 을 다시 그리지 않는다.
원본을 다시 그리면 사람이 쌓아 둔 편집분이 전부 무효가 되기 때문이다(DECISIONS D2).

```bash
node tools/apply.mjs --vocab                          # 쓸 수 있는 커맨드 목록
node tools/apply.mjs <slide.kgslide> --cmds -  --dry  # 표준입력으로 넣고 시험 실행
node tools/apply.mjs <slide.kgslide> --cmds cmds.json # 적용
```

계약 위반이면 적용하지 않고 원본을 그대로 둔다. 몇 번째 커맨드가 문제인지 알려 준다.

**어느 요소인지 알아내는 법 — 사용자가 붙여 넣는 참조 쪽지**

사용자가 편집기에서 요소를 고르고 `참조 복사`(Ctrl+Shift+R, 선택하면 뜨는 도구막대에도 있다)를
누르면 아래 쪽지가 클립보드에 담긴다. 채팅창에 붙여 넣은 것을 그대로 근거로 삼는다.

```
@kg 장표 "<제목>" (<프로젝트>)
   slide: <장표 id>
   nodes: <노드 id 들, 쉼표로>
   note: <있을 때만>
   ── 고른 것 N개 ──
   [<위계>] <그 요소의 글자>
```

읽는 법
- `slide` → 파일은 `<프로젝트>/slides/<slide>.kgslide`
- `nodes` → 커맨드의 `id` / `ids` 에 그대로 넣는다
- `note` 의 "하위 N개 포함" → 부모를 골랐으니 그 안쪽까지 함께 다루라는 뜻
- `── 고른 것 ──` 은 사람이 확인하려고 붙인 것이다. **여기 적힌 글자를 근거로 추측하지 말고**
  반드시 `nodes` 를 써라. 같은 글자가 여러 곳에 있을 수 있다.

쪽지 없이 "왼쪽 두 번째 박스" 같은 말만 있으면, 고쳐 달라는 곳이 어디인지 되물어라.
추측해서 엉뚱한 노드를 고치는 것보다 한 번 묻는 편이 싸다.

구조 자체를 바꿔야 하면(3단 나열 → 도넛 등) 새 장표를 만드는 것으로 다루고,
기존 편집분이 폐기됨을 사용자에게 먼저 알린다.

## 5단계 — 마무리(cooldown)

장표 작도가 끝나는 시점에 사용자에게 묻는다.

1. 이 장표를 어떤 타입으로 카탈로그에 남길지 (`types/*.json` 갱신)
2. 다음 장표로 넘어갈지, 프로젝트를 마감할지

타입 카탈로그는 파일이어야 누적된다. 대화에 남기지 않는다.

## 사람이 확인해야 넘어가는 지점

- 1단계 시작 전 — 원본 존중 여부
- 2단계 직후 — 미리보기 확인
- 4단계에서 구조 재작도가 필요할 때 — 편집분 폐기 동의
- 5단계 — 타입 카탈로그 갱신

이 네 곳 외에는 묻지 않고 진행한다.
