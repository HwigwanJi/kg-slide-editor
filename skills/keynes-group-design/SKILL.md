# 케인즈그룹 장표 디자인 시스템 스킬

이 스킬은 한국 공공기관·정책컨설팅 보고서용 **고밀도 분석 장표**를 케인즈그룹 브랜드로 생성한다.

## 먼저 읽을 것
0. `WORKFLOW.md` — **작도→미리보기→적재→트리밍→마무리** 전체 규약. 장표 작업은 여기서 시작한다.
   사람에게 물어봐야 하는 네 지점(원본 존중 여부·미리보기 확인·편집분 폐기 동의·타입 카탈로그)이 정해져 있다.
1. `README.md` — 회사/산출물 컨텍스트, 문체(CONTENT FUNDAMENTALS), 시각 기반(VISUAL FOUNDATIONS), 아이콘 규칙, 파일 인덱스.
2. `DENSITY.md` — 장표 밀도의 핵심 규칙. **§0 작도 프로세스(반복 채움 루프)**, **§7 핵심 레이아웃 공식**, **§9 box-in-x 모듈 카탈로그**는 반드시 숙지.
3. `EYE_CATCHING.md` — "한 장 = 하나의 도해" 시선 집중 문법(컴포넌트가 하는 말, 박스 안/밖 규칙).
4. `slides/` — 17종 레이아웃 예시. 새 장표는 가장 가까운 파일을 복제·변형해 시작한다.

## 핵심 원칙 (요약)
- **상단 위계 고정**: 섹션번호 · 제목 · 세부주제 · 우상단 index형 챕터 탭 · 헤더 메시지띠(흰 바탕·파란 글씨·가운데, 하단 그림자) · 헤더 우측 그라데이션 미디어.
- **본문은 반프리폼 box-in-x**: 모든 박스 안을 x 모듈(도넛·막대·100%스택·미니flowchart·벤다이어그램·허브스포크·셰브론·벤토·매트릭스·타임라인·스펙트럼·교환·As-is→To-be 등)로 채운다. 큰 빈 박스 금지.
- **유목화**: 평문 나열 금지 — `핵심키워드 → 하위내용 2`(`.kg-grp`).
- **무채색 우선**: 그레이 50~70% : 연파랑 25~35% : 네이비·빨강 ≤5%. 파랑 과다 금지.
- **표 금지**: `<table>` 대신 `display:grid` 박스 그리드(handcraft).
- **마스터 그리드**: 소주제(가운데정렬+얇은 밑줄)가 1:3 / 2:2 / 3:1 비율을 결정, 본문은 `.kg-content.s-*`로 분할. 항상 하단 마진까지 가득 채움.
- **연결선**: 내용과 정확히 매핑. 행이 안 맞으면 사다리꼴 그라데이션(불투명→투명).

## 만드는 법
- **A4 가로(1280×905) 비율**: 스타일은 `colors_and_type.css` + `kg-slide.css`를 링크하고 `.kg-slide`(A4 가로 1280×905) 안에서 클래스 조합. 16:9로 잡지 말 것.
- 폰트는 `fonts/`(Pretendard 300–900), 로고는 `assets/`(컬러=밝은 배경, 음영/반전=네이비 배경).
- **폰트는 충분히 크게** — 본문 16px / 소주제 20px / 메시지 23px 이하로 줄이지 말 것.
- **레이아웃 다양화**: 장표마다 서로 다른 레이아웃 패밀리·x 모듈을 쓴다. 한 유형(가장 경제적인 형태)으로 전체를 밀지 말 것. 한 슬라이드 안 소주제 간에도 같은 비주얼 반복 금지.
- **컴포넌트 사용 명시(design sync)**: 각 슬라이드 최상단 `@dsCard` 주석의 subtitle에 사용한 컴포넌트를 라벨링한다(예: `x: 도넛·타임라인 / 연결: 사다리꼴 / 라벨: kg-cornern`). 화살표·번호 등은 반드시 시스템 컴포넌트(`kgx-*`, `kg-cornern`, `kg-right`, `kg-chev` 등)를 쓰고 임의로 그리지 않는다.
- 단일 장표 뷰어는 `slides/kg-standalone.css` + `slides/kg-fit.js`, 덱 뷰어는 `slides/index.html` 참고.
- 17개 레이아웃 예시는 `slides/` 안에 있으니 가장 가까운 것을 복제·변형한다. **예시 내용을 그대로 베끼지 말고 동일 문법으로 새 구조를 설계.**

## 콘텐츠 작성 규칙 (엄수)

**기준 문체**: 중앙부처 3급 이상이 결재한 공문서. 이 기준을 통과하지 못하는 문구는 장표에 올리지 않는다.

- 본문에는 **메타적·설계언어적 표현을 절대 넣지 않는다**(예: "box-in-x 구조", "소주제 영역", "레이아웃", "컴포넌트", "시사점 블록" 등 제작 용어). 장표에는 오직 분석 내용만 담는다.
- **헤더 메시지띠는 공백 포함 70자 안에서 한 줄로 끝낸다.** 장표에서 가장 먼저 읽히는 한 문장이다. 두 줄로 넘어가면 띠가 두꺼워져 본문이 눌리고, 한눈에 들어오는 문장이라는 성격도 잃는다. 길어지면 수식을 걷어내고 결론만 남긴다.
- **판단·사고 과정을 노출하지 않는다.** "~ 필요", "~ 시급", "~로 보임", "~로 판단됨" 처럼 무엇이 부족한지를 적지 말고, 무엇을 하는지를 적는다. 장표는 검토 메모가 아니라 결론이다.
- **자극적 표현 금지.** 등급·순위를 선정적으로 다루지 않는다("D 탈출", "꼴찌", "위기 극복"). 사실과 조치로만 쓴다.
- **약어·구어 금지.** 첫 등장에서 정식 명칭을 쓴다("경평" 아님, "경영실적 평가").
- **실무 은어 금지.** 얼라인·정렬(전략 정합의 뜻)·인사이트·니즈·액션아이템·온보딩·스코프·리소스 등 영어 음차를 쓰지 않는다. 정책 문서의 표준 용어로 옮긴다.
- 마케팅 어투·자기 평가("혁신적", "획기적") 금지. 판단은 발주처가 한다.
- 이모지·이모티콘·유니코드 픽토그램 미사용.
- 한 텍스트 상자 안에 서로 다른 서식을 섞지 않는다. 편집기가 한 상자를 한 단위로 다루므로 섞이면 그 상자는 편집이 막힌다. 강조가 필요하면 상자를 나눈다.

작도를 마치면 `AI-Polish` 스킬로 문구를 한 번 더 훑는다. 규칙 중 기계가 잡을 수 있는 것은
편집기 검사(`npm run lint:slides`)가 잡으므로, 넘기기 전에 지적 0건을 확인한다.

## 산출물 형태
시각 산출물(슬라이드·목업·throwaway 프로토타입)을 만들 때는 자산을 복사해 정적 HTML로 출력한다.
프로덕션 코드 작업이면 자산을 복사하고 이 규칙을 읽어 브랜드 전문가로서 디자인한다.

사용자가 별도 지시 없이 이 스킬을 호출하면, 무엇을 만들고 싶은지 묻고 몇 가지 질문을 한 뒤 HTML 산출물 또는 프로덕션 코드를 내는 디자이너로서 행동한다.
