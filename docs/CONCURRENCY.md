# 동시 쓰기 — 편집기와 명령줄이 같은 폴더를 쓴다

1~4 을 넣었다(2026-07-27). 5(쓰기 충돌 검사)는 1이 들어가 교차 손실이 없어졌으므로 두지 않았다.
아래는 무엇이 왜 깨졌고 어떻게 갈랐는지의 기록이다.

| | 무엇 | 어디 |
|---|---|---|
| 1 | 필드 소유권 분리 | `src/core/merge.ts` · `tools/ingest.mjs` · `project.folder.ts` |
| 2 | 폴더 열 때 남의 덱을 밀지 않음 | `editor.ts` — 사람이 누른 다시 읽기일 때만 저장 |
| 3 | 같은 origin 은 사본을 만들지 않음 | `editor.ts` `adoptSlide` |
| 4 | 디스크 변경 자동 반영 | `project.ts` `stamps` · `editor.ts` 2초 확인 |

## 증상 (2026-07-27 실측)

편집기에서 폴더를 열어 둔 채 `npm run ingest` 를 돌렸다. 8초 사이에 이렇게 됐다.

```
15:24:42  편집기가 7731467a.kgslide 저장
15:24:48  편집기가 38caac6b.kgslide 저장
15:24:50  편집기가 6ee8ac90 새 사본 생성 — "발주기관 이해 … (사본)"
          deck.json 두 번 덮임 — 프로젝트 이름이 "JDC_정성제안서" → "기본 프로젝트" 로,
          방금 적재한 장표가 목록에서 사라짐
```

결과로 같은 장표가 두 벌씩 남았다. 한쪽은 사람이 쌓은 편집분을 갖고 원본이 낡았고,
다른 쪽은 최신 원본을 갖고 편집분이 없다.

| 파일 | 원본 | 편집분 |
|---|---|---|
| `38caac6b` | 낡음 | 패치 8 · 묘비 1 · 테마 5 · 떼어냄 1 |
| `13c3d348` | 최신 | 없음 |
| `7731467a` | 낡음 | 패치 10 · 묘비 2 · 그룹 1 · 테마 4 · 떼어냄 3 |
| `7e655fbb` | 최신 | 없음 |

## 원인 — 한 파일에 주인이 둘이다

`.kgslide` 한 파일을 양쪽이 **통째로** 쓴다.

- `tools/ingest.mjs` 는 `ingestHtml`(`src/core/audit-bundle.ts`)로 **새 문서를 만들어** 덮는다.
  `importKgHtml` 은 빈 오버레이를 가진 문서를 돌려주므로 `patches`·`tree`·`theme`·`stack` 이 사라진다.
- 편집기 `saveSlide`(`src/adapters/project.folder.ts`)는 **메모리 문서를** 덮는다.
  그 문서의 `source` 는 열었을 때 읽은 것이라, 그 사이 명령줄이 갈아끼운 원본이 사라진다.

나중에 쓴 쪽이 이긴다. `docs/DECISIONS.md` D5 가 "같은 원본을 다시 넣으면 id 를 유지한다"까지는
정했지만, **id 만 잇고 내용은 통째로 갈아치운다**는 점이 규칙에 빠져 있었다.

## 고치는 순서

### 1. 필드 소유권을 나눈다 (계약 스키마 변경 없음)

| 필드 | 주인 | 쓰는 쪽 |
|---|---|---|
| `source` · `canvas` · `title` | 작도 | `tools/ingest.mjs` |
| `patches` · `tree` · `theme` · `stack` | 사람 | 편집기 |

양쪽 모두 **읽고 → 자기 필드만 바꾸고 → 쓴다.**

- `ingest` — 기존 `.kgslide` 가 있으면 읽어 오버레이를 그대로 들고 `source` 만 갈아끼운다.
- 편집기 `saveSlide` — 디스크의 파일을 다시 읽어 `source` 를 가져다 붙이고 오버레이만 자기 것으로 쓴다.

이 하나로 교차 손실이 성립하지 않게 된다. 같은 필드를 두 주인이 쓰는 경우가 없기 때문이다.
**"재적재가 편집분을 지운다"와 "편집기가 작도분을 지운다"가 동시에 사라진다.**

주의 — 오버레이는 원본 구조 경로(`n.0.1`)로 노드를 가리킨다. 원본이 바뀌면 같은 경로가
다른 요소를 가리킬 수 있다. 옮기기 전에 노드마다 확인한다.

- 경로가 사라졌으면 옮기지 않는다.
- 경로는 남았지만 태그·클래스가 다르면 옮기지 않는다.
- 옮기지 못한 것은 **반드시 보고한다.** 조용히 버리지 않는다.

`theme` 은 위계(role) 기준이라 원본과 무관하므로 무조건 옮겨도 된다.
`tree.added` 는 `a…` id 라 원본 경로와 겹치지 않는다.

### 2. 폴더를 열 때 남의 덱을 밀어넣지 않는다

지금은 브라우저 저장소 프로젝트의 덱이 폴더를 덮어써서 이름과 id 가 바뀐다.
`openFolder` → `reloadProject`(`src/app/editor.ts`)는 **읽기만** 해야 한다.
목록은 D6 규칙대로 `slides/*.kgslide` 를 훑어 만들고, `deck.json` 은 순서로만 쓴다.

### 3. 같은 `origin` 은 사본을 만들지 않는다

`발주기관 이해 (사본)` 이 생긴 자리다. `placeByOrigin`(`src/core/deck.ts`)을 타지 않는
경로가 있다. 같은 `origin` 이 이미 있으면 그 자리를 갱신한다 — D5 규칙 그대로.

### 4. 디스크 변경을 화면에 반영한다

`FileSystemObserver` 는 아직 쓸 수 없다. 대신 메타데이터만 확인한다.

- 창이 포커스를 받을 때, 그리고 2초 주기로 `deck.json` 과 열려 있는 장표의 `lastModified` 를 읽는다.
  파일 내용을 읽지 않으므로 싸다.
- 바뀌었으면 **`source` 만** 다시 읽어 캔버스를 다시 그린다. 오버레이는 메모리 것을 유지한다.
- 글자 편집 세션이 열려 있는 동안에는 다시 그리지 않는다(AGENTS R4).

여기까지 들어가면 편집기를 열어 둔 채로 명령줄 작업이 가능해진다.
지금은 새로 그릴 때마다 새로고침하고 폴더를 다시 골라야 한다.

### 5. 쓰기 충돌 검사 (필요해지면)

1이 들어가면 교차 손실이 없어지므로 당장은 필요 없다.
그래도 넣는다면 `SlideDoc.rev`(정수)를 두고 쓸 때마다 +1, 쓰기 직전 디스크의 `rev` 와
비교해 다르면 다시 읽어 자기 필드만 재적용한다.
`CONTRACT_VERSION` 5 → 6, `src/contract/migrate.ts` 에 `rev` 기본값 0 부여
(`docs/SAVE_CONTRACT.md` 의 "버전 올리기" 절차).

## 곁들여 고칠 것 — 폴더 핸들이 새로고침에 풀린다

`pickProjectFolder` 가 돌려준 핸들을 어디에도 보관하지 않는다.
새로고침할 때마다 `폴더 열기` 를 다시 눌러 같은 폴더를 찾아 들어가야 한다.
핸들을 IndexedDB 에 넣어 두면 권한 확인 한 번으로 이어진다.

## 그 전까지의 회피책

**편집기를 열어 둔 채로 명령줄이 폴더에 쓰지 않는다.**
쓸 일이 있으면 편집기 탭을 닫고, 쓴 뒤에 다시 연다.
