# 도메인 모델 — 무엇이 있고 어떻게 이어지는가

DB 가 없으므로 ERD 는 그릴 것이 없다. 대신 **문서 모델**을 적는다.

말의 뜻은 [GLOSSARY.md](GLOSSARY.md), 왜 그렇게 했는지는 [FEATURES.md](FEATURES.md),
근거가 된 대화는 [INTERVIEW.md](INTERVIEW.md).

**여기에 필드 목록을 옮겨 적지 않는다.** 그건 계약 파일이 진실이고, 복사하는 순간 갈라진다.
여기서는 **무엇이 무엇인지와 누가 쓰는지**만 말한다.

---

## 물건과 관계

```
프로젝트
  ├─ 덱              장표의 순서.  ★ 목차가 곧 존재다 — 목차에 없으면 장표가 아니다
  ├─ 장표 N개
  ├─ 자산            그림
  ├─ 도형 라이브러리   기본도형·연결선 모음
  ├─ 골격 라이브러리   와이어프레임 모음
  └─ titlebar 라이브러리

장표
  ├─ 뿌리 컨테이너 1개   장표 전체가 컨테이너 하나다
  ├─ 메모              쪽지. 쌓인다
  └─ 출처              어느 와이어프레임에서 나왔나 (기록일 뿐, 구속하지 않는다)
```

## 장표는 컨테이너 하나다

**장표를 이루는 물건은 컨테이너 하나뿐이다.** 나머지는 전부 그 안에 담긴다.

```
컨테이너
  ├─ 담을 것    자식컨테이너 · 캔버스 · 단일 기본도형 · 글상자 · 이미지 · 평면 · 비움
  ├─ 제 영역    없음 / 위 / 아래 / 좌 / 우 + 두께
  ├─ 마진       기본 마진(제 영역도 받음) · 계약마진(자식과의 간격)
  └─ 서식       배경 · 테두리 · 모서리 · 그림자
```

`자식컨테이너` 가 담을 것 중 하나이므로 **"부모인가" 를 따로 두지 않는다.** 고르면 곧 부모다.

### 왜 하나로 통일했는가

이름만 다른 같은 것이 흩어지는 것을 막기 위해서다. 실측 — 53장에서 `머리 + 본문 카드` 가
`.bx`(5장) `.blk`(5장) `.card`(5장) `.col`(10장) 넷으로 흩어져 있었다. 개념은 하나인데
매번 새로 만들었기 때문이다.

titlebar 도 특별한 물건이 아니라 **컨테이너 하나가 생기고 그 안에 내용이 들어가는 것**이다.

## 벤토그리드 — 바깥의 규칙

컨테이너들은 **겹치지 않고 빈틈없이** 영역을 채운다. 여백조차 빈 컨테이너로 둔다.
하나를 늘리면 옆이 줄어든다. 자리를 손으로 맞출 일이 없다.

**안쪽은 다르다.** 캔버스 안에서는 도형이 겹치고 떠 있고 선으로 이어진다.
**격자는 바깥, 자유는 안쪽.**

## 캔버스 안 — 파라메트릭 도식

```
캔버스
  └─ 도식
      ├─ 기본도형     모양·색·테두리·글자
      ├─ 슬라이서     도형을 행·열로 가른다 (표)
      ├─ 리피터       개수만큼 찍어낸다
      ├─ 선택 + 이펙터  찍어낸 것 중 골라 값을 바꾼다
      └─ 연결선

  ──(bake · 되돌릴 수 없음)──▶  개별 도형 목록
```

bake 해도 **컨테이너는 남는다.** 풀리는 것은 도식뿐이다.

**부분 bake 를 두지 않는 까닭** — 경계를 흐리지 않기 위해서다.
파라메트릭이면 AI 가 통째로 다시 만들어도 되고, bake 됐으면 사람이 손댄 것이다.
반쯤 사람 것인 덩어리가 생기면 매번 따져야 한다.

## 노드를 가리키는 법 — 여기가 주춧돌이다

오버레이는 노드를 **이름**으로 가리킨다. 이름은 만들 때 정해지고 그 뒤로 바뀌지 않는다.

지금 시스템은 이름이 아니라 **자리**(`n.2.1.0` = 3번째 자식의 2번째 자식)였다.
그래서 원본이 조금만 바뀌어도 가리키는 것이 달라졌고, 이 하나에서 나머지가 전부 파생됐다.

| 증상 | 뿌리 |
|---|---|
| AI 가 다시 그리면 사람의 편집분이 깨진다 | 자리로 가리킴 |
| 그래서 AI 만 다시 그릴 수 있다 → 힘의 비대칭 | 〃 |
| 그래서 AI 는 구조를 못 바꾼다 → 100:100 불가 | 〃 |
| 깨진 것을 건지는 방어 코드가 필요하다 | 〃 |
| 5만 번이면 누적 손실 | 〃 |

**이름으로 바꾸면 다섯이 동시에 사라진다.** 표에 행을 끼워도 기존 이름은 그대로고,
새 노드만 새 이름을 받는다.

> 실측 — 자리 기반일 때 AI 가 원본을 한 번 다시 그리자 고아 패치 4건이 생겼고
> **아무도 알리지 않았다.**

## 누가 무엇을 쓰는가

한 파일에 주인이 둘이면 나중에 쓴 쪽이 이겨 상대의 작업이 사라진다. 그래서 **각자 자기 것만 쓴다.**

| 것 | 주인 | 언제 |
|---|---|---|
| 원본 · 캔버스 규격 | 작도 | 장표를 처음 만들 때 한 번 |
| 오버레이 · 메모 | 사람과 AI **둘 다** | 자기 차례일 때 |
| 소유 · 리비전 | 시스템 | 넘길 때마다 |

지금 시스템은 여기서 **사람** 과 **AI** 를 갈랐다. 사람은 오버레이만, AI 는 원본까지.
그것이 비대칭의 근원이었다. 새 모델에서는 **둘 다 오버레이만 쓰고, 원본은 아무도 안 고친다.**

읽고 → 자기 것만 바꾸고 → 쓴다. 쓰기 직전에 리비전을 확인해, 내가 읽은 뒤 바뀌었으면 멈춘다.

## 한 장표에 한 손

같은 시각에 두 손이 닿지 않는다. 그래서 **충돌 해소가 필요 없다.**

```
사람이 2장을 쥔다        AI 는 2장에 들어오지 않는다
AI 가 3장을 쥔다         사람은 3장을 열 수 없다
아무도 안 쥔 장표         누구든 가져갈 수 있다
```

전역 모드는 예외다 — AI 가 덱 전체를 훑는 동안(예: 소제목 크기 통일) 사람은 아무 장표도
가져가지 못한다. 반쪽만 적용된 통일은 안 하느니만 못하기 때문이다.

쥔 쪽이 죽으면 잠금이 풀린다. 전역 작업이 중간에 죽으면 **어디까지 적용됐는지가 남아야** 한다.

## 한 바퀴

```
사람이 와이어프레임을 고른다
        ↓
컨테이너를 나누고, 각 자리에 무엇을 담을지 정한다
        ↓
AI 가 채운다 — 못 한 것은 메모에 남긴다
        ↓
사람이 이어받아 다듬는다.  캔버스는 focus room 에서
        ↓
검사가 넘침·겹침·글자·문구를 잡는다
        ↓
내보낸다 — 원본 또는 사본
```

가운데 두 칸이 5만 번 돈다. **이 도구가 지키려는 것은 그 왕복이다.**
