이 도구의 말은 대부분 한국어 도메인 용어다. 코드의 변수명·주석·화면 문구가 전부 이 어휘로
돌아가는데 정의된 곳이 없어서, 새로 온 사람은 `keepSlot` 이 왜 "빈 자리" 인지 코드를 읽어야
알 수 있었다.

근거는 [INTERVIEW.md](INTERVIEW.md). 새 저장소로 옮길 때 함께 간다.

표시 — **(새)** 는 인터뷰에서 정해진 것, 나머지는 지금 시스템에서 이어지는 말.

## ★ 컨테이너 — 장표를 이루는 단 하나의 물건 **(새)**

**컨테이너는 그냥 사각형 영역(필드)이다.** 그 자체로 무엇이라기보다 성질이 이렇다.

- 안에 컨테이너가 **또 들어간다.** 그 안의 배치는 무궁무진하다
- 테두리를 **가질 수도 있고 안 가질 수도** 있다
- 담는 것이 무엇이냐에 따라 편집 방식이 달라진다

**층으로 보지 않는다.** 층 안에 층 안에 층이 실제로 있을 수 있어서, 층으로 세기 시작하면
끝없이 복잡해진다. 대신 **가장 큰 것부터 그린다** — 이것이 가장 중요한 원칙이다.

그래서 "컨테이너가 몇 개냐" 는 **어느 깊이를 보느냐**의 문제다. 큰 상자 하나 안에 작은 상자
둘이면 1 이라 해도 2 라 해도 틀리지 않는다. 다만 **처음 셀 때는 가장 크게 갈리는 선을 따른다.**

> 실측 — 인사평가 체계도(상단 흐름도 + 하단 표 셋)를 **제목 줄** 기준으로 세어 7 이라 답했으나
> 원칙대로면 먼저 **상·하 2덩이**다. 제목이 아니라 **가장 크게 갈리는 선**이 먼저다.

### 담을 것 — 컨테이너가 무엇을 가지는가

사람이 컨테이너를 눌러 정한다. 정하고 나면 그에 맞는 편집이 열린다.

| 담을 것 | 뜻 | 편집 |
|---|---|---|
| **자식컨테이너** | 나눠서 자식을 담는다 | 나누기 · 합치기 |
| **캔버스** | 도식을 그리는 자유 공간 | focus room 에서 파라메트릭 편집 |
| **단일 기본도형** | 도형 하나 | 컴포넌츠 탭에서 속성 편집 |
| **글상자** | 글자 | 위계 · 서식 |
| **이미지** | 그림 파일 | 넣기 · 맞춤 |
| **평면(plain)** | 칠한 면 | 채움(색·무늬) · 테두리 |
| **비움** | 아무것도 안 담는다 | 여백을 만들려고 둔다 |

> `자식컨테이너` 가 담을 것 중 하나이므로 "부모인가" 를 따로 둘 필요가 없다.
> 고르면 곧 부모가 된다.

### 제 영역 (field)

부모가 되어도 **자식에게 나눠 주지 않는 자기 몫의 자리**를 둘 수 있다.
**자식들에게 걸린 마진을 적용받지 않아** 가장자리까지 꽉 찬다.

없음 / 위 / 아래 / 좌 / 우 중에 고르고 두께를 준다.
지금까지 "띠형 제목" 이라 부르던 것이 이 자리다 — **제목이 특별한 것이 아니라
제 영역에 글자를 담은 것뿐이다.** 도형을 담아도 되고 그림을 담아도 된다.

### 마진 — 두 종류다

| 말 | 뜻 |
|---|---|
| **기본 마진** | 컨테이너 안쪽 여백. 좌·우·상·하. **제 영역도 이것을 받는다** |
| **계약마진** | 자식컨테이너와 맺는 간격. 자식들 사이, 그리고 자식과 제 영역 사이 |

```
┌──────────────────────────┐  컨테이너 경계
│ ↔ 기본 마진                │
│  ┌────────────────────┐  │
│  │▓▓▓▓ 제 영역 ▓▓▓▓▓▓▓│  │  기본 마진 안 · 계약마진 밖
│  ├────────────────────┤  │
│  │ ┌─────┐ ↔ ┌─────┐ │  │  계약마진이 자식들 사이
│  │ │ 자식 │   │ 자식 │ │  │
│  │ └─────┘   └─────┘ │  │
│  └────────────────────┘  │
└──────────────────────────┘
```

**제 영역이 가장자리까지 꽉 차 보이는 까닭**이 이것이다 — 기본 마진만 받고 계약마진은 안 받는다.

### 나누기와 합치기

| 말 | 뜻 |
|---|---|
| **나누기(split)** | 행·열로 가른다. **전체 크기는 그대로**고 안에서 나눠 갖는다 |
| **빠른 나누기** | 자주 쓰는 꼴을 한 번에 — 통짜 · 1:3 · 3:1 · 1:1 · 2×2 |
| **합치기(merge)** | 나눈 것을 도로 붙인다. **붙어 있고 사각형이 되는 경우만** |
| **맞추기** | 고른 컨테이너들끼리 너비를 같게 · 높이를 같게 |

### 퀵액션 — titlebar 붙이기

여러 조작을 한 번에 하는 것. 손으로 하면 넷이다 — 나누기 → 글상자 넣기 → 서식 → 크기 맞추기.

**titlebar 도 컨테이너다.** 특별한 물건이 아니라 **컨테이너가 하나 생기고 그 안에 내용이
들어간다.** 라이브러리에서 골라 오므로 서식이 제각각으로 흩어지지 않는다.

| | 어디에 | 무엇이 줄어드나 |
|---|---|---|
| **outside titlebar** | 상자 **밖**, 사이에 여백 | 원래 컨테이너가 그만큼 줄어든다 |
| **inside titlebar** | 상자 **안** | 나머지 영역이 줄어든다. 이 자리가 곧 **제 영역**이다 |

안쪽 마진은 파라미터다. 0 이면 가장자리까지 꽉 차고, 값을 주면 들여쓴다.

### 벤토그리드 — 컨테이너에만 적용된다

컨테이너들이 **서로 겹치지 않고 빈틈없이** 영역을 채운다. 크기는 제각각이어도 된다.
그래서 자리를 손으로 맞출 일이 없고, 하나를 늘리면 옆이 줄어든다.
**여백조차 빈 컨테이너로 둔다** — 빈틈이 없어야 하기 때문이다.

**컨테이너 안쪽은 벤토그리드가 아니다.** 도식이 격자에 갇히면 곤란하다 —
도형이 겹치고 떠 있고 선으로 이어지는 것이 도식이다. **격자는 바깥, 자유는 안쪽.**

## 캔버스와 도식 **(전부 새)**

| 말 | 뜻 |
|---|---|
| **캔버스** | 도식을 그리는 공간. **벤토그리드를 받지 않는다** — 자유 배치, 겹침 허용 |
| **focus room** | 캔버스만 따로 여는 작업창. 포토샵처럼. **휴리스틱 편집은 여기서 한다** |

**왜 따로 여는가** — 장표 화면과 캔버스는 조작 체계가 다르다. 밖에서는 컨테이너를 나누고
옮기고, 안에서는 도형을 그리고 겹친다. 한 화면에 섞으면 "지금 무엇을 끌고 있는가" 가
매번 헷갈린다. 그리고 컨테이너가 장표의 6분의 1이면 그 좁은 자리에서 도형을 그릴 수 없다.

### 도식을 그리는 말 — PPT + C4D

PPT 는 도형을 하나하나 그려야 하고, 프리셋은 자유도가 없다. 그 사이를 C4D 방식으로 잇는다 —
**적은 원시형 × 파라미터 × 조합.** 완성품 목록을 늘리는 것으로는 안 풀린다. 중간값이 없기 때문이다.

| 말 | 뜻 |
|---|---|
| **기본도형** | 도식의 원시형. 모양(사각·둥근·셰브론·사다리꼴·원·화살표)·색·테두리·글자가 파라미터 |
| **슬라이서** | 도형 하나를 행·열로 가른다. **영역이 먼저, 개수가 나중.** 표가 여기서 나온다 |
| **리피터** | 개수만큼 찍어낸다. **개수가 먼저, 영역이 나중.** 전체가 늘어난다 |
| **선택** | 찍어낸 것 중 어느 것에 손댈지. 첫째·마지막·N번째·홀짝·범위 |
| **이펙터** | 파라메트릭 연결을 끊지 않고 값을 바꾼다. 선택과 짝을 이룬다 |
| **Step** | 순서에 따라 값이 점점 변하는 이펙터. 시작값 → 끝값 |
| **시드** | 무작위 이펙터가 같은 그림을 다시 내게 하는 값. **문서에 저장해야 한다** |
| **연결선** | 두 도형을 잇는다. 화살촉·꺾임이 파라미터 |

> 슬라이서와 리피터를 가르는 것이 핵심이다. 표를 만들 때 **"전체 폭 내에서"** 열 너비를
> 조정한다는 것이 슬라이서라는 증거다 — 리피터면 폭을 늘릴 때 전체가 커진다.

### 파라메트릭 상태와 bake

```
파라메트릭 상태  ──(bake · 되돌릴 수 없음)──▶  개별 도형 상태
```

- **파라메트릭 상태** — 파라미터로만 만진다. 색·균등·병합의 **순서는 자유**다
- **bake** — 원시로서의 값을 잃고 개별 도형 속성이 남는다. **전체가 한꺼번에** 넘어간다
- **개별 도형 상태** — 하나씩 지우고 옮긴다

bake 해도 **컨테이너는 그대로 남는다.** 풀리는 것은 그 안의 도식뿐이다.

부분 bake 를 두지 않는 까닭은 경계를 흐리지 않기 위해서다.
**파라메트릭 = AI 가 통째로 다시 만들어도 되는 것, bake 됨 = 사람이 손댄 것.**
반쯤 사람 것인 덩어리가 생기면 매번 따져야 한다.

### 크기가 바뀔 때

컨테이너가 줄면 안의 캔버스도 준다. 포토샵에서 그룹을 끄는 것처럼 **통째로 스케일**한다.
다만 **비율 잠금**을 켜면 글자 크기는 유지된다(단축키 있음). 기본값은 글자 유지 —
그러지 않으면 브랜드 규격이 깨진다.

## 협업 **(전부 새)**

| 말 | 뜻 |
|---|---|
| **핸드오프** | 사람 ↔ AI 가 작업을 넘기는 일. 이 도구가 지키려는 단 하나 |
| **소유(Me / AI)** | 이 장표를 지금 누가 쥐고 있나. 한 장에는 한 손만 |
| **전역 모드** | AI 가 덱 전체를 훑는 상태. 배타적이다 — 사람은 아무 장표도 못 가져간다 |
| **메모** | 장표에 붙는 쪽지. **덮지 않고 쌓인다.** 사람도 AI 도 쓴다 |
| **안정 id** | 노드의 이름. **자리가 아니라 이름이다** — 무엇을 끼워 넣어도 기존 id 는 그대로다 |
| **리비전** | 이 문서가 몇 번째 상태인가. 내가 읽은 뒤 바뀌었으면 쓸 때 막힌다 |

> **"무너진다" 의 뜻** — 화면이 깨지는 것이 아니라 **넘겨받은 쪽이 낡은 것 위에서 작업하는 것**이다.
> 사람이 ver0.1 을 만들었는데 AI 가 ver0.0 에서 시작하면, 이후 무엇을 잘해도 결과는 어긋난다.
