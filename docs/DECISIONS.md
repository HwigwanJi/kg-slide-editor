# 결정 기록

되돌리면 비싼 결정만 남긴다. 이유를 함께 적는 이유는, 나중에 "왜 이렇게 했지" 하고
다시 논의하는 비용을 없애기 위해서다. 뒤집을 때는 이유를 반박하고 이 문서를 고친다.

---

## D1. 슬라이드는 개별 파일, 덱은 인덱스만 (2026-07-27)

```
프로젝트폴더/
  deck.json          순서·제목·메타만. 장표 내용을 담지 않는다.
  slides/*.kgslide   장표 한 장 = 파일 하나 (SlideDoc JSON)
  library/*.svg      도형 라이브러리
  library/index.json 태그·설명·텍스트 슬롯 정의
  preview/*.png      장표별 미리보기
```

**이유** — 장표 1장이 원본 HTML을 통째로 품고 있어 수백KB다. 덱을 단일 JSON으로 두면
20장짜리가 수MB가 되고, 한 장을 고칠 때마다 전체를 다시 쓴다. 파일 분리는 git diff 도
장표 단위로 깔끔하게 만들고, "개별 장수를 만들어 편집기로 불러온다"는 작업 방식과도 맞는다.

**따르는 규칙** — `deck.json` 은 장표 내용을 절대 담지 않는다. 순서의 진실은 `deck.json`
하나이고, 장표 파일은 자기가 몇 번째인지 모른다.

## D2. AI 수정은 커맨드로 발행한다 (2026-07-27)

AI가 장표를 고칠 때 HTML을 다시 그리지 않는다. `core/commands.ts` 의 커맨드 JSON을 발행한다.

**이유** — 우리 계약은 "원본 불변 + 패치"다. AI가 HTML을 새로 그리면 노드 경로가 어긋나
쌓아 둔 편집분이 전부 무효가 된다. 사람이 30분 다듬은 결과가 AI 호출 한 번에 사라진다.
커맨드로 받으면 사람이 누르는 버튼과 같은 통로를 지나므로 실행취소·이력·검증이 그대로 적용된다.

**한계** — 구조 재작도(예: 3단 나열을 도넛으로 바꾸기)는 커맨드로 표현되지 않는다.
그 경우는 새 장표를 만드는 것으로 다루고, 기존 편집분이 폐기됨을 사용자에게 알린다.

**따르는 규칙** — 커맨드 union 이 곧 AI가 쓸 수 있는 어휘다. 커맨드를 추가하면 AI의 능력이
늘고, 커맨드 밖의 조작을 AI에게 허용하지 않는다.

## D3. 미리보기 PNG는 Playwright 로 찍는다 (2026-07-27)

**이유** — KG 장표는 CSS 그라데이션·`clip-path`·`mask-image`·웹폰트에 크게 의존한다.
html2canvas 계열 재현기는 셰브론·사다리꼴·도넛을 뭉갠다. Playwright 는 실제 Chromium 이라
화면과 100% 일치하고, CLI 라 장표를 그린 직후 바로 찍어 보여 줄 수 있다.

**비용** — 브라우저 바이너리 약 100MB. 개발 의존성으로만 둔다.

## D4. 도형 라이브러리 v1 은 점편집을 넣지 않는다 (2026-07-27)

라이브러리 개체는 순수 `.svg` 파일이다. 편집기가 하는 일은 배치·크기·KG 색토큰 교체·
텍스트 슬롯 교체까지다.

**이유** — 점·선 편집은 앵커·베지어 핸들·스냅·전용 실행취소가 모두 새 서브시스템이라
편집기 규모가 체감상 절반 더 커진다. 실무에서는 "이 화살표 좀 더 휘게" 라고 말해
다시 그리는 편이 빠르다. 순수 SVG 로 두면 공유·버전관리·타 도구 열람이 공짜로 따라온다.

**뒤집을 조건** — 다시 그리기 왕복이 실제로 병목이 되면 그때 붙인다.

## D5. 스킬은 HTML 을 뱉고, 적재는 도구가 한다 (2026-07-27)

작도 산출물은 KG 장표 HTML 이다. 편집기 문서(`.kgslide`)를 직접 뱉지 않는다.
`tools/ingest.mjs` 가 HTML 을 읽어 `slides/*.kgslide` 를 만들고 `deck.json` 에 등록한다.

**이유** — HTML 은 사람이 브라우저로 바로 열어 검수할 수 있다. 편집기 문서는 그렇지 않다.
그리고 임포트 규칙(자산 경로·잠금·제목)을 도구에 다시 쓰면 편집기와 갈라지므로,
편집기 어댑터를 그대로 실행한다.

**따르는 규칙** — 같은 원본을 다시 넣으면 장표 id 를 유지한다. 그래야 사람이 쌓아 둔
편집분과 미리보기가 이어진다. id 가 바뀌면 그 둘이 통째로 끊긴다.

## D6 — 무엇이 있는가는 파일이 정한다

**문제.** 폴더에 `.kgslide` 가 6개 있는데 편집기 목록에는 2개만 떴다.
`deck.json` 이 순서만이 아니라 "무엇이 존재하는가" 까지 정하고 있었기 때문이다.
명령줄로 적재하거나, 다른 컴퓨터에서 그린 파일을 폴더에 넣어도 화면에 나타나지 않았다.
여러 대에서 나눠 그려 모으는 방식과 정면으로 어긋난다.

**결정.** 진실을 둘로 나눠 각자에게 맡긴다.

| 무엇 | 어디가 진실인가 |
|---|---|
| 어떤 장표가 존재하는가 | `slides/*.kgslide` 파일 |
| 어떤 순서인가 | `deck.json` |
| 장표의 내용·제목 | 각 `.kgslide` |

폴더를 읽을 때마다 둘을 맞춘다.
목차에 있고 파일도 있으면 목차 순서를 지키고, 파일만 있으면 만든 시각 순으로 뒤에 붙이고,
목차에만 있으면 뺀다. 제목은 언제나 파일에서 다시 읽는다 — 목차의 제목은 낡을 수 있다.

**따라오는 것.** 폴더에 파일을 떨어뜨리면 다시 읽기만 눌러도 목록에 나타난다.
지우려면 파일을 지운다(목록의 × 가 그렇게 한다). 목차에서만 빼는 방법은 없다.

## 전체 사이클

```
1. 작도    Claude Code + keynes-group-design  ->  source/*.html
2. 적재    npm run ingest                     ->  slides/<id>.kgslide + deck.json
3. 편집    편집기에서 폴더 열기               ->  .kgslide 에 패치가 쌓인다
4. 검사    npm run lint:slides                ->  넘침·문구·위계
5. 미리보기 npm run preview:slides            ->  preview/<id>.png
```

명령줄이 폴더에 쓰면 편집기는 **다시 읽기**(홈 탭)로 가져온다. 편집기는 폴더를 감시하지 않는다.
브라우저 저장소에서 시작했다면 **폴더로 저장**(슬라이드 탭)으로 한 번 파일로 꺼낸다.

3단계 이후의 장표에 2단계를 다시 돌리면 쌓아 둔 패치가 사라진다.
편집한 장표를 고칠 때는 `npm run apply` 커맨드 경로를 쓴다.
